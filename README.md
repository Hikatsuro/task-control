# TaskControl

Учебная система планирования и контроля задач. React использует Django REST Framework через `/api`. В базе хранятся пользователи, отделы, заказчики, проекты, задачи, история, комментарии, вложения, уведомления, заказы оплаты и подписки.

Сайт открывается по одному адресу — `http://127.0.0.1:8080`: и при запуске на компьютере (Vite пересылает `/api` в Django), и в Docker (nginx пересылает `/api` в Django).

## Запуск на компьютере

Понадобятся Python 3.12 и Node.js 22.12+ или 24 LTS. Откройте два терминала из корня проекта. Команды ниже для PowerShell.

В первом запустите Django.

```powershell
cd backend
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py shell -c "import seed_full_demo"
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8000
```

Django при старте читает `backend/.env`: адрес сайта, ключи PayPal Sandbox, настройки AI-помощника. Файл исключён из Git, ключи храните только в нём. `gunicorn` и `whitenoise` из `requirements.txt` нужны только в Docker; если они не установились на Windows, локальный запуск работает и без них.

Во втором запустите React.

```powershell
cd frontend
npm ci
npm run dev -- --port 8080
```

Откройте [страницу входа](http://127.0.0.1:8080/login). Открывайте сайт как `127.0.0.1:8080` или `localhost:8080`, в `backend/.env` адрес задан в `TASKCONTROL_FRONTEND_URL`. Локальный запуск по умолчанию использует SQLite. Для PostgreSQL задайте `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_HOST` и `POSTGRES_PORT`; база должна быть создана заранее.

## Запуск через Docker Compose

Понадобится [Docker Desktop](https://docs.docker.com/get-docker/) с Compose v2. Compose поднимает три контейнера: `db` (PostgreSQL 16), `backend` (Django + gunicorn) и `frontend` (nginx со сборкой React). Nginx отдаёт сайт и пересылает `/api`, `/admin` и `/static` в Django, поэтому сайт и API работают с одного адреса, а сессия и CSRF — без настройки CORS.

```powershell
Copy-Item .env.example .env
docker compose up --build
```

При старте `backend` сам применяет миграции, собирает статику админки и, если `TASKCONTROL_SEED_DEMO=1`, заполняет базу демоданными (повторный запуск добавляет только отсутствующие записи). Откройте <http://127.0.0.1:8080/login>.

| Переменная в `.env` | Назначение | По умолчанию |
| --- | --- | --- |
| `DJANGO_SECRET_KEY` | Секретный ключ Django; для показа подойдёт любая строка | `change-me-for-local-demo` |
| `DJANGO_DEBUG` | `1` включает режим отладки | `0` |
| `TASKCONTROL_PORT`, `TASKCONTROL_FRONTEND_URL` | Порт и адрес сайта; адрес используется в письмах, для возврата из PayPal и в ссылках AI-сводки | `8080`, `http://127.0.0.1:8080` |
| `TASKCONTROL_SEED_DEMO` | `1` — заполнить базу демоданными при старте | `1` |
| `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD` | Параметры PostgreSQL | `taskcontrol` |
| `PAYPAL_CLIENT_ID`, `PAYPAL_CLIENT_SECRET` | Ключи PayPal Sandbox; без них оплата выключена, остальной сайт работает | пусто |
| `OLLAMA_BASE_URL`, `TASKCONTROL_AI_MODEL` | Ollama на компьютере (не в контейнере) и модель AI-помощника | `http://host.docker.internal:11434/v1`, `qwen2.5:3b` |

Полезные команды: `docker compose up -d` (в фоне), `docker compose logs -f backend` (журнал Django и письма восстановления), `docker compose exec backend python manage.py test core` (тесты), `docker compose down` (остановить, данные сохранятся), `docker compose down -v` (удалить и базу). После изменения кода — `docker compose up --build`.

## Тестовая оплата через PayPal Sandbox

Оплата идёт в тестовом режиме PayPal: деньги не настоящие, нужен только бесплатный аккаунт разработчика.

1. Войдите на <https://developer.paypal.com> (подойдёт обычный аккаунт PayPal или новый). Откройте **Apps & Credentials**, переключатель вверху — **Sandbox**, нажмите **Create App**, тип — *Merchant*.
2. Скопируйте *Client ID* и *Secret* в `backend/.env` (локальный запуск) или в корневой `.env` (Docker): `PAYPAL_CLIENT_ID=…`, `PAYPAL_CLIENT_SECRET=…`. Перезапустите Django.
3. В **Testing Tools → Sandbox Accounts** уже есть тестовый покупатель (*Personal*). Откройте его, посмотрите email и пароль — ими вы будете «платить». Реальный аккаунт PayPal для оплаты не используйте.
4. Войдите как `demo_manager`, откройте **Тариф** → «Оплатить через PayPal», войдите тестовым покупателем и подтвердите платёж.

Как это работает:

- Сервер создаёт заказ в PayPal (`POST /api/billing/orders/`) и возвращает ссылку на оплату. Ключи PayPal в браузер не попадают.
- После возврата на сайт сервер сам захватывает платёж (`POST /api/billing/orders/capture/`), сверяет статус и сумму и только затем включает тариф на 30 дней. Повторное открытие страницы результата тариф не продлевает.
- «Отменить» в PayPal ведёт на страницу результата: заказ помечается отменённым, тариф не меняется.
- Заказ видит и подтверждает только руководитель, который его создал.
- **Аннулировать подписку** (кнопка на странице тарифа при активной подписке) сразу возвращает тариф к «Базовому», чтобы оплату можно было показать снова. История платежей остаётся. Возврат денег не выполняется: в Sandbox они не настоящие.

## AI-помощник

Страница **AI-помощник** — чат по задачам и проектам. Языковая модель работает на этом компьютере через [Ollama](https://ollama.com) и сама выбирает инструменты чтения: список проектов, задачи проекта, задачи всех проектов, подробности задачи (описание, комментарии, история, файлы). Можно спросить «Что сейчас просрочено?», «Какие задачи ждут моей проверки?», «О чём задача про макет и что писали в комментариях?».

Кнопка **Сводка по проекту** даёт отчёт по выбранному проекту: итоги по статусам и задачи, требующие внимания, считает сервер (всегда точно), вывод и рекомендацию пишет модель.

Ограничения помощника:

- видит только то, что пользователь видит в кабинете: руководитель — свои проекты, сотрудник — свои задачи; администратору помощник недоступен;
- только читает: ни один инструмент ничего не меняет, на просьбу «удали» или «назначь» помощник отвечает, что это делается в кабинете;
- отвечает только о задачах и работе команды; тексты задач и комментариев для модели — данные, а не команды;
- вопрос — до 1000 символов, история — до 12 сообщений, до 4 обращений к инструментам на ответ, не больше 20 запросов в минуту от пользователя (`TASKCONTROL_AI_RATE`).

Подробнее и запуск агента из консоли — в `backend/ml/README.md`.

1. Установите Ollama с <https://ollama.com/download> (Windows: установщик `OllamaSetup.exe`). После установки он работает в фоне на `127.0.0.1:11434`.
2. Скачайте модель. Для чата рекомендуется `qwen2.5:7b` (около 4,7 ГБ): она заметно точнее; `qwen2.5:3b` (около 2 ГБ) быстрее, но чаще путается.

   ```powershell
   ollama pull qwen2.5:7b
   ```

3. Укажите модель в `backend/.env`: `TASKCONTROL_AI_MODEL=qwen2.5:7b` — и перезапустите Django.
4. Откройте **AI-помощник** и задайте вопрос. На обычном компьютере ответ занимает до минуты.

Если Ollama не запущен или модель не скачана, страница скажет об этом прямо.

Агента можно запустить и из консоли, как отдельный клиент API (вход под `demo_manager`, чтение задач по HTTP), из папки `backend` при запущенном сайте на 8080:

```powershell
.\.venv\Scripts\python.exe -m ml.project_summary_agent
```

## Что показать

| Логин | Что открыть |
| --- | --- |
| `demo_manager` | Обзор, проекты и заказчики, отчёты, просрочки и приёмка задачи, AI-сводка, оплата тарифа и аннулирование |
| `demo_employee` | Мои задачи, обсуждение, файл и отправка на проверку |
| `demo_admin` | Пользователи, отделы, настройки команды |

Пароль всех вымышленных аккаунтов — `TaskControl-demo-26`. Повторное заполнение добавляет отсутствующие демонстрационные записи и сохраняет сделанные изменения.

Проект «Корпоративный портал» содержит задачу «Проверить макет карточки задачи» на проверке. В ней есть комментарии, история и файл с критериями. «Настроить фильтры по срокам» показывает просрочку. В календаре и отчёте используются те же серверные задачи.

Настройки тем действуют на текущий браузер. Предпочтения уведомлений и профиль хранятся на сервере. Письма восстановления выводятся в терминал Django (в Docker — в `docker compose logs backend`). Скачивание файлов доступно только пользователям, которые видят задачу.

Проверка: `.\.venv\Scripts\python.exe manage.py test core` из `backend/` (API, оплата с подменённым PayPal, AI-помощник с подменённой моделью), `npm run lint`, `npm run test`, `npm run build` и `npm run test:e2e` из `frontend/`. ML-прогноз сроков пока демонстрационный.
