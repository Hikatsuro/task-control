# Предложение контракта для будущего Django API

Это предложение для согласования с malisiousintenttttt и rr0semary, а не уже подключённые адреса. Frontend сейчас работает локально.

Путь `/api/v1/`. Маршруты сайта остаются `/app/...`. Источник текущего пользователя на сервере — аутентифицированный запрос, не `user_id` или роль из тела запроса. Способ входа нужно согласовать отдельно; для размещения frontend и Django на одном origin подходят серверная сессия и CSRF-защита изменений.

| Метод и адрес | Назначение |
| --- | --- |
| GET `/me/` | Текущий пользователь, роль, настройки |
| GET/POST `/projects/` | Доступные проекты / создание |
| GET/PATCH `/projects/{id}/` | Карточка / редактирование |
| GET `/projects/{id}/tasks/` | Только разрешённые пользователю задачи проекта |
| GET/POST `/tasks/` | Фильтруемый список / создание |
| GET/PATCH `/tasks/{id}/` | Карточка / редактирование |
| POST `/tasks/{id}/transitions/` | Статус и причина возврата |
| GET/POST `/tasks/{id}/comments/` | Обсуждение |
| GET/POST `/tasks/{id}/attachments/` | Метаданные и multipart-загрузка |
| DELETE `/tasks/{id}/comments/{id}/` | Удаление собственного комментария |
| DELETE `/tasks/{id}/attachments/{id}/` | Удаление собственного вложения |
| GET `/tasks/{id}/activity/` | История изменений |
| GET/POST/PATCH `/clients/`, `/users/`, `/departments/` | Справочники с проверкой ролей |
| GET/PATCH `/notifications/` | Личные уведомления и прочитанность |

Предлагаемый ответ для AI-инструмента:

```json
{
  "count": 1,
  "next": null,
  "results": [
    {
      "id": "42",
      "project_id": "12",
      "title": "Подготовить API задач",
      "assignee": { "id": "2", "username": "malisiousintenttttt" },
      "status": "in_progress",
      "priority": "high",
      "due_date": "2026-11-20",
      "completed_at": null,
      "url": "/app/tasks/42"
    }
  ]
}
```

Frontend использует camelCase (`projectId`, `dueDate`, `completedAt`); адаптер преобразует snake_case. Идентификаторы фронт трактует как непрозрачные строки. Даты без времени — `YYYY-MM-DD`, события — ISO 8601 с часовым поясом. Статусы: `new`, `in_progress`, `in_review`, `done`; просрочка не отдельный статус.

Для списка нужны параметры проекта, исполнителя, статуса, приоритета, срока, поиска и сортировки; пагинация не должна терять задачи в AI-сводке. Пустой список — успешный ответ, отказ в доступе — отдельная ошибка, а не подстановка тестовых данных. Недоступный объект можно скрывать ответом 404; согласовать это поведение единообразно.

Операции изменения возвращают обновлённые сущности и события. Клиентские UUID начального набора не считаются серверными идентификаторами. При подключении API локальные демонстрационные данные не отправляются автоматически на сервер.

LLM и PayPal вызываются сервером; секреты не попадают в frontend. AI получает только доступные текущему пользователю задачи. Если AI находится в том же Django-процессе, функция чтения может вызывать общий сервис прав и выборки без HTTP-запроса к самому себе. ML-индекс текущей демоверсии должен быть заменён результатом обученной и проверенной модели, без заявления реальной точности по синтетике.
