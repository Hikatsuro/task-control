# TaskControl — frontend

Русскоязычное приложение для планирования и контроля выполнения задач. Реализовано по исходной светлой палитре Figma: молочный фон, тёмный текст, оранжевые акценты, Roboto и Roboto Condensed. Главная страница показывает интерактивный процесс работы; кабинет сохраняет быстрые спокойные переходы.

В разделе «Как это работает» на главной показан путь документа от назначения задачи до встречи с заказчиком. Этапами управляют прокрутка и кнопки. Есть светлая и тёмная темы, а также упрощённый режим. [Открыть раздел](http://127.0.0.1:5187/#process).

В чистой копии офис и движение персонажей рисуются средствами Three.js. Если в `public/models/people-local/` лежат все четыре локальные модели Renderpeople, сборка использует их для демонстрации на этом компьютере. Файлы моделей исключены из Git.

Для локального показа можно оставить GLB в отдельной папке и запустить сайт с ними. Пример для PowerShell после `npm ci`:

```powershell
$env:TASKCONTROL_LOCAL_MODELS_DIR = 'C:\путь\к\people-local'
npm run dev -- --port 5187
```

В этой папке должны быть `eric-seated.glb`, `carla-seated.glb`, `eric-handshake.glb` и `claudia-handshake.glb`. Параметр предназначен для локального показа. Для обычных сборок он не нужен. [Условия Renderpeople](https://renderpeople.com/general-terms-and-conditions/) описывают отдельные ограничения на передачу файлов моделей, включая изменённые версии.

## Подключение

Кабинет по умолчанию использует Django. Порядок запуска, демонстрационные учётные записи и описание базы находятся в [README проекта](../README.md). Адрес сервера для прокси Vite задаётся переменной `TASKCONTROL_BACKEND_URL`, по умолчанию используется `http://127.0.0.1:8012`.

Адаптер ответов Django находится в `src/data/django.ts`. Для автономного показа интерфейса можно перед запуском установить `VITE_DEMO_MODE=true`. Этот режим использует данные браузера и подходит для существующих тестов локального прототипа.

Тема сохраняется в браузере под ключом `taskcontrol.theme.v1` и применяется до запуска React. Карта экранов доступна через «Помощь».

## Маршруты демонстрации

- `/#process` — история документа на главной.
- `/cinematic` — та же история на отдельной странице.
- `/workflow#process` — предыдущая сцена с возвратом задачи на доработку.

## Проверки

```sh
npm run typecheck
npm run lint
npm run test
npm run test:e2e
npm run build
```

Сквозные проверки используют установленный Microsoft Edge в headless-режиме. Для другого компьютера можно изменить `channel` в `playwright.config.ts` или установить Chromium через Playwright. Отчёт: `playwright-report/index.html`. Скриншоты: `qa/`. Проверки создают изолированные контексты браузера и не меняют данные пользовательского профиля.

Статическая production-сборка создаётся в `dist/`; `npm run preview` запускает её локально. При будущем размещении сервер должен отдавать `index.html` для frontend-маршрутов. Размещение в интернете в этой задаче не выполняется.
