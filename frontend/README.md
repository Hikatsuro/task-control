# TaskControl — frontend

Русскоязычное приложение для планирования и контроля выполнения задач. Реализовано по исходной светлой палитре Figma: молочный фон, тёмный текст, оранжевые акценты, Roboto и Roboto Condensed. Главная страница показывает интерактивный процесс работы; кабинет сохраняет быстрые спокойные переходы.

В разделе «Как это работает» на главной показан путь документа от назначения задачи до встречи с заказчиком. Этапами управляют прокрутка и кнопки. Есть светлая и тёмная темы, а также упрощённый режим. [Открыть раздел](http://127.0.0.1:5173/#process).

В чистой копии офис и движение персонажей рисуются средствами Three.js. Если в `public/models/people-local/` лежат все четыре локальные модели Renderpeople, сборка использует их для демонстрации на этом компьютере. Файлы моделей исключены из Git.

Для локального показа можно оставить GLB в отдельной папке и запустить сайт с ними. Пример для PowerShell после `npm ci`:

```powershell
$env:TASKCONTROL_LOCAL_MODELS_DIR = 'C:\путь\к\people-local'
npm run dev
```

В этой папке должны быть `eric-seated.glb`, `carla-seated.glb`, `eric-handshake.glb` и `claudia-handshake.glb`. Параметр предназначен для локального показа. Для обычных сборок он не нужен. [Условия Renderpeople](https://renderpeople.com/general-terms-and-conditions/) описывают отдельные ограничения на передачу файлов моделей, включая изменённые версии.

## Запуск

В терминале из папки `frontend` выполните:

```sh
npm ci
npm run dev
```

Требуется Node.js 22.12+ или 24 LTS. После запуска откройте [TaskControl](http://127.0.0.1:5173/). При следующих запусках достаточно `npm run dev`.

## Светлая и тёмная тема

Откройте **Настройки → Внешний вид** и выберите «Светлая» или «Тёмная». Изменение применяется сразу ко всему сайту, включая главную и вход. Тёмная палитра: олива `#151813`, поверхности `#22271F`, светлый текст `#EEF1E8`, терракотовый акцент `#F28C64`.

Настройка сохраняется в `localStorage` под ключом `taskcontrol.theme.v1`, отдельно от проектов и демопрофилей. Она общая для этого браузера и адреса сайта, сохраняется между запусками и синхронизируется в открытых вкладках. Очистка данных сайта удаляет выбор. Если браузер запретит запись, тема применится на текущей странице, а интерфейс сообщит, что сохранить её не удалось.

Сохранённая тема применяется до запуска React. Для печати/PDF используется светлое оформление независимо от выбранной темы.

## Что работает

- Главная, вход и демонстрационные формы восстановления доступа.
- Создание и редактирование проектов, участники, даты, фильтры, завершение и архив. Архивирование требует приёмки всех задач.
- Создание и редактирование задач, назначение, сроки в пределах проекта, приоритеты, поиск, сортировка, фильтры.
- Общие данные для списка, Kanban с перетаскиванием, календаря, карточек, отчётов и демосводок. На телефоне и с клавиатуры статус также меняется через карточку.
- Жизненный цикл: новая → в работе → на проверке → выполнена. Приёмка — руководителю; возврат требует причины. Фактическая дата и журнал сохраняются.
- Комментарии, локальные вложения до 10 МБ, скачивание, подтверждение удаления собственного комментария или файла.
- Заказчики и контакты; команда и доступные задачи каждого сотрудника.
- Администрирование пользователей и отделов, блокировка, редактирование профиля.
- Уведомления о событиях, прочитанность, предпочтения. Напоминания о сроках формируются при открытии приложения, без фонового сервиса.
- Отчёт за период **по плановым срокам**, диаграммы, настоящий файл `.xlsx`. PDF — через кнопку «Печать / PDF» и сохранение в диалоге браузера.
- Локальный демонстрационный тариф и экраны успешной оплаты, ошибки, ожидания. Демосводки по правилам и объяснимый индекс риска.

В `Помощь → Карта экранов` перечислены **все 53 макета Figma** и соответствующие страницы/вкладки/состояния. Несколько макетов одной карточки объединены в общий компонент. Справочные экраны остаются в разделе помощи.

## Данные и ограничения

Данные сохраняются в `localStorage` с валидацией схемы и версией. Файлы — в отдельной IndexedDB `taskcontrol-files-v1`. Привязка к браузеру, профилю браузера и адресу сайта: `localhost` и `127.0.0.1` считаются разными источниками. Пользуйтесь одним адресом. Приватный режим может удалять данные после закрытия.

Сервер, PostgreSQL, отправка почты, push, настоящая авторизация, LLM, обученная ML-модель и PayPal Sandbox **не подключены**. Соответствующие интерфейсы явно помечены демонстрационными. Секретных ключей и реальных платежей нет. Для настоящих данных и совместной работы нужна серверная реализация прав и хранения.

При переполнении хранилища приложение сообщает, что изменение не сохранено. Повреждённая запись не заменяется молча: появляется восстановление с возможностью скачать исходную запись. Сброс демо — через настройки профиля admin; он удаляет локальные изменения и вложения. Пока следует работать в одной вкладке: конфликтное редактирование несколькими вкладками не разрешается автоматически.

## Структура и подключение API

- `src/domain/` — типы, валидация, права и команды предметной области.
- `src/data/` — начальные данные, хранение снимка и вложений, карта экранов.
- `src/state/` — состояние приложения, очередь сохранения и обратная связь.
- `src/components/` — общие элементы, каркас кабинета и таблица задач.
- `src/pages/` — страницы по функциональным областям.
- `tests/` — сквозные пользовательские сценарии и визуальные проверки.

`localRepository` сохраняет локальный снимок, **не является HTTP-контрактом**. При подключении Django потребуется адаптер команд/ответов, согласование авторизации и серверных идентификаторов. Предложение контракта — в `docs/api-contract.md`. Сервер повторно проверяет права, вычисляет служебные даты и не доверяет роли из браузера.

## Маршруты демонстрации

- `/#process` — история документа на главной.
- `/cinematic` — та же история на отдельной странице.
- `/workflow#process` — предыдущая сцена с возвратом задачи на доработку.

## Проверки

```sh
npm run typecheck
npm run lint
npm run test
npm run test:e2e
npm run build
```

Сквозные проверки используют установленный Microsoft Edge в headless-режиме. Для другого компьютера можно изменить `channel` в `playwright.config.ts` или установить Chromium через Playwright. Отчёт: `playwright-report/index.html`. Скриншоты: `qa/`. Проверки создают изолированные контексты браузера и не меняют данные пользовательского профиля.

Статическая production-сборка создаётся в `dist/`; `npm run preview` запускает её локально. При будущем размещении сервер должен отдавать `index.html` для frontend-маршрутов. Размещение в интернете в этой задаче не выполняется.
