# API для фронтенда: как получить задачи

Ответ на пункты «Согласовать адрес API и поля» и «Подключиться к серверу».
Сервер: Python + Django + Django REST Framework + PostgreSQL (первая версия, код в /backend).

---

## 1. Коротко

| Вопрос                    | Ответ                                                       |
| ------------------------- | ----------------------------------------------------------- |
| Адрес для получения задач | `GET /api/tasks/?project_id={id}`                           |
| Поле «название»           | `title`                                                     |
| Поле «срок»               | `due_date` (строка `YYYY-MM-DD` или `null`)                 |
| Поле «статус»             | `status` (одно из: `todo`, `in_progress`, `review`, `done`) |
| Базовый адрес (локально)  | `http://localhost:8000`                                     |
| Формат                    | JSON                                                        |
| Авторизация               | сессия (cookie) после входа через `/api/auth/login/`        |

---

## 2. Запуск сервера локально

```bash
docker compose up -d db              # PostgreSQL (или без него: тогда SQLite)
pip install -r requirements.txt
python manage.py migrate
python manage.py createsuperuser     # получит роль «администратор»
python manage.py runserver           # http://localhost:8000
```

Пользователей и роли создаёт администратор в `http://localhost:8000/admin/`
(поле «Роль»: `admin` / `manager` / `employee`). Для проверки экранов создайте
одного руководителя и одного сотрудника.

---

## 3. Как работает вход

1. `POST /api/auth/login/` с телом `{"username": "...", "password": "..."}`.
   Сервер ставит cookie `sessionid` и `csrftoken`. В ответе — пользователь и его роль.
2. Во всех последующих запросах браузер сам отправляет cookie. Для `fetch` нужно `credentials: "include"`.
3. Для запросов **не-GET** (`POST`, `PATCH`) добавьте заголовок `X-CSRFToken` со значением из cookie `csrftoken`.
   Без него сервер ответит `403`. Сам `login` заголовка не требует.
4. `POST /api/auth/logout/` — выход (ответ `204`).
5. Без входа любой запрос вернёт `403`.

> **CORS:** в первой версии не настроен. Пока фронтенд и сервер на разных адресах
> (разные порты тоже считаются), браузер заблокирует запросы. Варианты: прокси в dev-сервере
> фронтенда (например, `/api` → `http://localhost:8000`) или попросить добавить `django-cors-headers`.

## 4. Все адреса

| Метод и адрес                     | Для чего                               | Кто может               |
| --------------------------------- | -------------------------------------- | ----------------------- |
| `POST /api/auth/login/`           | Вход                                   | все                     |
| `POST /api/auth/logout/`          | Выход                                  | вошедшие                |
| `GET /api/auth/me/`               | Текущий пользователь и роль            | вошедшие                |
| `GET /api/customers/`             | Список заказчиков                      | руководитель            |
| `POST /api/customers/`            | Добавить заказчика                     | руководитель            |
| `GET /api/projects/`              | Список доступных проектов              | руководитель, сотрудник |
| `POST /api/projects/`             | Создать проект                         | руководитель            |
| `GET /api/projects/{id}/`         | Один проект                            | руководитель, сотрудник |
| `GET /api/tasks/?project_id={id}` | Задачи проекта                         | руководитель, сотрудник |
| `POST /api/tasks/`                | Создать задачу и назначить исполнителя | руководитель            |
| `GET /api/tasks/{id}/`            | Одна задача                            | руководитель, сотрудник |
| `PATCH /api/tasks/{id}/`          | Изменить разрешённые поля              | руководитель, сотрудник |

`project_id` необязателен: без него придут все доступные пользователю задачи.

## 5. Формат данных

### Задача (`/api/tasks/`)

```json
{
  "id": 12,
  "project": 3,
  "title": "Подготовить макет главной",
  "description": "Описание задачи",
  "assignee": 7,
  "status": "in_progress",
  "due_date": "2026-11-30",
  "created_by": 2,
  "created_at": "2026-11-16T10:15:00+05:00",
  "updated_at": "2026-11-16T12:40:00+05:00"
}
```

`GET /api/tasks/` возвращает **массив** таких объектов (без обёртки и без пагинации).

| Поле                       | Тип                            | Примечание           |
| -------------------------- | ------------------------------ | -------------------- |
| `id`                       | число                          |                      |
| `project`                  | число                          | id проекта           |
| `title`                    | строка                         | **название**         |
| `description`              | строка                         | может быть пустой    |
| `assignee`                 | число или `null`               | id исполнителя       |
| `status`                   | строка                         | **статус**, см. ниже |
| `due_date`                 | строка `YYYY-MM-DD` или `null` | **срок**             |
| `created_by`               | число                          | id руководителя      |
| `created_at`, `updated_at` | строка (ISO 8601)              |                      |

### Статусы

| Значение `status` | Что показать пользователю |
| ----------------- | ------------------------- |
| `todo`            | К выполнению              |
| `in_progress`     | В работе                  |
| `review`          | На проверке               |
| `done`            | Принята                   |

Подписи на русском в ответе сервера **не приходят**. Их нужно сопоставить на фронтенде.

### Пользователь (`/api/auth/me/`, ответ на login)

```json
{
  "id": 7,
  "username": "ivan",
  "first_name": "Иван",
  "last_name": "Петров",
  "role": "employee"
}
```

`role`: `admin`, `manager`, `employee`.

### Проект (`/api/projects/`)

```json
{
  "id": 3,
  "name": "Сайт для ACME",
  "description": "",
  "customer": 1,
  "manager": 2,
  "members": [7, 8],
  "is_archived": false,
  "created_at": "2026-11-10T09:00:00+05:00"
}
```

Создание: `{"name": "...", "customer": 1, "members": [7, 8]}` (`description` необязательно; `manager` ставится автоматически).

### Заказчик (`/api/customers/`)

```json
{ "id": 1, "name": "ACME", "contact": "info@acme.test", "created_at": "..." }
```

## 6. Что видит и может каждая роль

Сервер сам фильтрует данные. Чужие проекты и задачи не приходят в списках, а при прямом обращении по id дают `404`.

|                                      | Администратор | Руководитель              | Сотрудник                     |
| ------------------------------------ | ------------- | ------------------------- | ----------------------------- |
| Проекты                              | пусто         | свои                      | где состоит в команде         |
| Задачи                               | пусто         | в своих проектах          | назначенные себе              |
| Заказчики, создание проектов и задач | нет           | да                        | нет                           |
| `PATCH` задачи                       | —             | все поля, принять/вернуть | только `status` у своих задач |

Администратор управляет учётными записями, рабочие данные ему не выдаются, поэтому экран задач для него будет пустым. Так задумано.

### Смена статуса (`PATCH /api/tasks/{id}/` с `{"status": "..."}`)

| Переход                                          | Кто может            |
| ------------------------------------------------ | -------------------- |
| `todo` → `in_progress` (начать работу)           | исполнитель          |
| `in_progress` → `review` (отправить на проверку) | исполнитель          |
| `review` → `done` (принять)                      | руководитель проекта |
| `review` → `in_progress` (вернуть)               | руководитель проекта |

Другие переходы вернут `400`.

---

## 7. Коды ответов

| Код                   | Когда                                                                                                                   |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| `200` / `201` / `204` | успех / создано / выход                                                                                                 |
| `400`                 | неверные данные, например недопустимый переход статуса или исполнитель не из проекта; тело вида `{"поле": "сообщение"}` |
| `401`                 | неверный логин или пароль (только при входе)                                                                            |
| `403`                 | не выполнен вход, нет прав на действие или нет CSRF-заголовка                                                           |
| `404`                 | объект не существует или недоступен этому пользователю                                                                  |

## 8. Как заменить чтение тестового файла запросом к серверу

Было (чтение тестового файла) → стало:

```js
// Вход (один раз)
await fetch("/api/auth/login/", {
  method: "POST",
  credentials: "include",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({ username, password }),
});

// Задачи проекта
async function loadTasks(projectId) {
  const res = await fetch(`/api/tasks/?project_id=${projectId}`, {
    credentials: "include",
  });
  if (!res.ok) throw new Error(`Ошибка ${res.status}`);
  const tasks = await res.json(); // массив
  return tasks.map((t) => ({
    id: t.id,
    name: t.title, // название
    deadline: t.due_date, // срок (может быть null)
    status: t.status, // todo | in_progress | review | done
  }));
}

// Смена статуса (нужен CSRF-заголовок)
function csrf() {
  return document.cookie
    .split("; ")
    .find((c) => c.startsWith("csrftoken="))
    ?.split("=")[1];
}
async function setStatus(taskId, status) {
  const res = await fetch(`/api/tasks/${taskId}/`, {
    method: "PATCH",
    credentials: "include",
    headers: { "Content-Type": "application/json", "X-CSRFToken": csrf() },
    body: JSON.stringify({ status }),
  });
  if (!res.ok) throw new Error(`Ошибка ${res.status}`);
  return res.json();
}
```

Адрес `/api/...` в примерах относительный: он работает при прокси на сервер. Иначе укажите полный базовый адрес.

Проверка из терминала:

```bash
curl -c cookies.txt -H "Content-Type: application/json" \
  -d '{"username":"ivan","password":"..."}' http://localhost:8000/api/auth/login/
curl -b cookies.txt "http://localhost:8000/api/tasks/?project_id=3"
```

## 9. Что пока не готово

- Комментарии, файлы, отчёты и архивирование проекта.
- API создания пользователей (их создаёт администратор в `/admin/`).
- Настройка CORS.
- Пагинация (списки приходят целиком).

Если экранам нужны другие названия полей или дополнительные данные
(например, имя исполнителя вместо его id), напишите, и я добавлю их в ответ.
